## 0.30.30 更新内容

修复 Android 本地终端的两个缺陷，均由实测发现。

- **修复 root 档在 Shizuku 未授权时谎报可用、连上后卡死。** root 档在 Shizuku-as-root 设备上
  走的是 Shizuku user service，因此和 ADB 档一样需要应用被 Shizuku 授权；但档位的可用性判定
  只看了「Shizuku 是否以 root 运行」，没看授权。表现是卡片显示 `Root` 且没有任何提示，连接后
  终端停在「Connecting to localhost…」约 15 秒，然后报 `TERMINAL_OPEN_FAILED`。更麻烦的是
  应用里唯一的授权入口只在「缺少 Shizuku 授权」这个 blocker 下才绘制，而 root 档的 blocker
  永远不可能是它 —— 用户在那张卡片上无从自救。现在 root 档走 Shizuku 时要求与 ADB 档相同的
  条件，并如实报出「缺少 Shizuku 授权」，卡片上直接给出授权按钮。
- **终端顶部的会话标识对本地会话显示它自己的名字。** 此前显示 `shell@localhost` —— 一个用户
  从未输入过的地址。这一处在 v0.30.29 的更新说明里已经写过，但改动当时没有随之提交，所以那一版
  的安装包并不包含它，本次补上。

### 验证与开放范围

- 两个缺陷都在 API 35 模拟器上按真实 UI 流程走通。root 档经 Shizuku-as-root 启动（服务器以
  uid 0 运行），连上后 `id -u` 为 0、SELinux 域为 `u:r:su:s0`（与 `adb root` 的 shell 同域），
  PTY 宿主链 `ofs_local_host → ofspty` 两者均为 uid 0。
- root 档的修复有回归测试 `LocalTierAvailabilityTest`（6 项）。已先回退修复确认目标用例会失败、
  其余 5 项照常通过，再打上修复确认全绿。
- 仪器测试在模拟器上全通过：ADB 档 4 项（含 uid 2000 断言）、跨 uid 回环 1 项（按 CI 配方手动
  预置宿主后单独跑）、宿主传输 8 项、应用档 8 项通过、1 项因该镜像没有 `stty` 跳过。
- 仍未在真机验收的项目没有变化：**root 档从未在真机上运行过**（没有已 root 的设备，真机
  `ro.boot.flash.locked=1`、无 `su`，其上限就是 ADB 档）、**PTY 窗口尺寸是否传到内核**未验证
  （模拟器镜像没有 `stty`）、Android 8/9/10 未实测。

### 发布过程记录

一条会反复浪费排查时间的事实，这次量清楚了：**Shizuku 的授权与 Android 运行时权限位双向解耦**。

- `pm grant <包名> moe.shizuku.manager.permission.API_V23` 会让 `dumpsys` 报 `granted=true`，
  但 `Shizuku.checkSelfPermission()` 仍然返回 DENIED，档位照旧降级。
- `pm revoke` 会把该权限行从 `dumpsys` 里整个移除，但应用**照常能连上** root 档。

两个方向都不起作用，只有 Shizuku 自己的 `RequestPermissionActivity`（点应用卡片上的授权入口）
能改。因此想复现「未授权」状态不能用 `pm revoke`，只能用**全新安装** —— 本次缺陷最初正是在
一次 `connectedDebugAndroidTest` 重装 APK 之后暴露出来的。判断真实状态请以进程表为准
（宿主进程的 uid），不要以 `dumpsys` 为准。
