## 0.30.32 更新内容

本次修复连接管理右键菜单在慢渲染或远程控制环境下的叠层与点击失效，并降低浮层的合成开销。

- **右键菜单始终只有一个。** 连接树原先为每个服务器/分组各挂一个非受控菜单；慢渲染时连续右键可能在前一个弹层挂载完成前再开一个，导致多个菜单叠在一起，点击“编辑”命中旧弹层或被遮挡。现在整棵树共用一个受控菜单，始终只显示一个，并作用于最后一次右键的服务器或分组。
- **菜单项点击恢复可靠。** 编辑、复制连接、复制 SSH 命令、删除，以及分组的新建连接、新建分组、重命名、删除，都从同一个菜单分派；菜单在 Esc、窗口失焦、缩放和滚动时自动关闭。
- **浮层改为实体表面。** 右键菜单、下拉框、Popover、连接编辑抽屉和设置弹窗不再使用 `backdrop-filter` 背景模糊，改为不透明表面，避免在 ToDesk 等远程控制或低性能 GPU 环境下对下层内容反复采样。标题栏、侧栏和状态栏的静态玻璃效果保留，可在“设置 → 减少透明效果”中关闭。

### 验证范围

- 新增连接树右键菜单回归：同一批次连续右键 3 个服务器，只保留 1 个可见菜单，点击“编辑”作用于最后一个目标；分组菜单同样覆盖。
- 组件与渲染层测试 678 项通过；类型检查、生产构建和体积预算检查通过。
- 未进行真实 ToDesk 会话与真实 RDP 主机互操作验收；发布工作流继续执行原有平台构建与门禁。

### English

Fix the connection manager context menu stacking and lost clicks under slow rendering or remote-control sessions, and reduce compositing cost for popups.

- **One context menu only.** Each server and group used to own an uncontrolled menu; under slow rendering a second right-click could open another menu before the first popup mounted and registered its outside-close listener, leaving menus stacked and Edit clicks hitting a stale popup. The tree now uses a single controlled menu that always shows one popup and acts on the last right-clicked server or group.
- **Reliable menu actions.** Connect, edit, duplicate, copy SSH command and delete, plus the group actions, are dispatched from that single menu; it closes on Escape, window blur, resize and scroll.
- **Opaque popup surfaces.** Context menus, selects, popovers, the connection editor drawer and settings dialogs no longer use `backdrop-filter`; they render on opaque surfaces so remote-control tools such as ToDesk and low-power GPUs no longer resample the content behind them every frame. Static title bar, sidebar and status bar glass remains and can be disabled in Settings → Reduce transparency.

Verification: a new regression fires three right-clicks in one batch and asserts a single visible menu and that Edit targets the last node; component/renderer suites pass 678 tests; typecheck, production build and bundle budget pass. Live ToDesk and RDP host acceptance were not performed; the release workflow keeps the existing platform gates.
