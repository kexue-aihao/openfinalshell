## 0.30.29 更新内容

修复 Android 本地终端的两个缺陷与一处显示问题，均由真机实测发现。

- **修复特权档（ADB shell / root）一开终端就失败**。`ShizukuHostLauncher.launch` 里那次 socket 连接跑在调用方的调度器上，而调用方是 `viewModelScope`（Main 线程），于是必然抛 `NetworkOnMainThreadException`。表现是会话显示已连接、但打开终端时报 `TERMINAL_OPEN_FAILED`、终端里没有可用的 shell。`su` 路径不受影响（它整个流程都在 IO 调度器里）。现在传输层在启动宿主时统一切到 IO，启动器自身也切一层。
- **修复「添加本地终端」看起来毫无反应**。表单渲染在列表最底部、屏幕可视区之下，点完什么都看不见。现在两个「添加」按钮在展开表单后都会自动滚到它；SSH 的「添加连接」是同一个形态，一并修掉。
- 终端页面顶部的会话标识对本地会话显示 `shell@localhost` —— 一个用户从未输入过的地址。现在改为显示该会话自己的名字。

### 验证与开放范围

- 两个档位都在 API 35 模拟器上按真实 UI 流程走通：应用档的 shell 以应用自身 uid 运行；ADB 档经 Shizuku user service 启动宿主，`/data/local/tmp` 下以 0700 暂存，shell 以 uid 2000 运行。日志无错误。
- 新增 `openingAShellFromTheMainDispatcherWorks`：从**主调度器**打开 shell（应用的真实路径），并配一个内联连接的启动器复刻旧行为。已先回退修复确认它会以 `NetworkOnMainThreadException` 失败，再打上修复确认通过 —— 这正是先前 33 项仪器测试全绿却漏掉它的原因：那些测试用 `runBlocking`，协程停在测试线程上。仪器测试现为 35 项全通过。
- 仍未在真机验收的项目没有变化：**root 档（uid 0）从未在真机上运行过**、**PTY 窗口尺寸是否传到内核**未验证（模拟器镜像没有 `stty`）、Android 8/9/10 未实测。
