# WinUI3 终端响应修复与诊断（2026-11-16）

## 范围与结论

依据授权实施 T1–T4，修改终端传输、后台解析、UI 快照与关闭流程，提供本地 SSH 重放、回归和压力工具。没有执行远端软件安装、发布版本或变更配置及存储格式。

基线证实：仅事件消费时，SSH.NET ShellStream 仍保留原始数据；接收 1 MiB 后保留 1,048,753 字节，60 秒窗口基线保留 16,380,292 字节。静态代码同时存在事件回调同步等待队列、UI 解析及隐藏标签停止消费的风险。可控基线没有复现死锁，不能将用户实际卡死直接归因为已证实死锁，也不能归因于框架差异。

## T1：复现与诊断

test/fixtures/testSshServer.mjs 新增原始字节重放：

~~~text
replay 2500000 0 32768
replay 10000000 10 32768
replay 10000000 100 13
stall-input
extended-output
drop-transport
~~~

参数依次为行数、分片延迟毫秒、包大小。每 16 行包含 ANSI、清行及 CR 进度，包含中文和 emoji。生成器等待 drain，Ctrl+C 取消代次。它不调用 apt/dpkg 或安装命令。慢速场景是应用层分片与延迟，未模拟 WAN 丢包、路由故障和 TCP 重传。

窗口 fixture 创建高输出、普通输入和慢速输出三个会话，每秒切换标签或设置视图，每 7 秒搜索，每 11 秒改变尺寸，结束发送 Ctrl+C。记录接收字节、应用队列、SSH 内部缓冲、进程内存、绘制和关闭耗时。处理器提供 ParsedBytes / ParseTime，独立压力工具记录解析时间。

心跳最多一个待执行请求，UI 只采样入队到执行延迟，后台统计并写日志。背景读取线程堆栈样例中 ShellStream.Read 等待在后台线程；样例不是死锁证据。

| 信号 | 优先检查 |
|---|---|
| UI 正常、接收不增长、队列为空 | 远端命令、网络或 SSH 接收；结合独立 exec 与服务端日志 |
| 接收增长、待处理字节增长 | 解析吞吐或消费回调 |
| 应用队列满、SSH 缓冲稳定在窗口内 | 背压，远端应等待窗口额度 |
| 解析正常、绘制停滞、UI 延迟上升 | UI 调度、Win2D 或其他窗口操作 |

## T2：异步读取与发送

每个终端只有一个后台 ShellStream 原始读取循环，单次至多 32 KiB。取消时后台断开 SSH、关闭流解除阻塞 Read / Flush，等待任务退出。移除输出 DataReceived 订阅与同步等待。输出泵显式后台启动，异步等待 64 块队列（至多 2 MiB 排队数据，另有一个最多 32 KiB 的生产者块）。有状态解码保留跨块字符，重连代次重置。

输入与协议回复进入容量 128 的后台发送队列并保持顺序；满时明确报错。连续尺寸变化共用信号并取最新值。取消已开始的发送会关闭传输，避免部分输入后继续发送。

上游 SSH.NET 默认会话接收窗口约 2 GiB。初版突发测试仍超过 8 MiB 并失败，因此最终改为本地源码依赖：终端专用 256 KiB 窗口，仅在 raw Read 后归还额度；网络监听不等待应用队列。扩展输出纳入同一流。SFTP、exec、转发及标准 shell factory 保持上游行为。固定源版本、MIT 和完整补丁位于 windows/ThirdParty/SSH.NET，发布输出包含授权文件。升级 SSH.NET 时需要维护该补丁并重新回归。

## T3：后台处理器

NativeTerminalProcessor 独占 libvterm，串行处理输出、键鼠、粘贴、尺寸、清屏、历史和快照。最多 32 KiB 提交，内部 2 KiB 分片，每约 2 ms 检查取消和交互命令。处理完成表示解析完成，与 UI 绘制无关。命令队列容量 128，处理器输出边界仅一块排队，没有每块 Task.Run 或无界输出队列。

隐藏标签持续解析；终端关闭而 SFTP/监控仍持有连接时保留处理器与工作区，最后一个关联标签关闭后释放。恢复终端复用整个工作区、原处理器与最新快照，避免 Win2D 画布从原父控件拆下后再次挂载失败。

## T4：UI 与生命周期

不可变快照含视口、屏幕、光标、模式和版本。后台最多每 50 ms 发布一次，内容不变不发布；每会话最多一个待执行 UI 刷新并读取最新快照。UI 没有 libvterm 调用和解析器锁。保留文字布局缓存，无障碍文字间隔约 350 ms，相同内容跳过。

搜索与复制通过处理器取得每批至多 512 行独立数据，匹配在后台，支持取消；尺寸变化取消搜索或复制。历史持续滚动时按批读取，因此结果属于实时历史，不承诺整个历史的一次性时间点快照。

关闭顺序为取消、断开 SSH / 关闭流、异步等待传输和输出泵、等待处理器释放 libvterm、释放绘图。新连接前等待旧输出完成屏障，代次隔离旧数据和回调。状态、历史、目录在 UI 边界派发。

## 运行方法

在仓库根目录，要求已有 .NET 10、npm 依赖与原生构建工具：

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/testNativeTerminalPipeline.ps1 -IncludeSshBurst
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/testNativeTerminalResponsiveness.ps1 -Seconds 600
~~~

窗口脚本构建 WinUI、复制隔离目录、启动本地 fixture 并记录 JSON 与心跳；检查 P99≤100 ms、最大心跳≤1 秒、清理≤3 秒和无错误。默认输出 build/terminal-responsiveness-20261116，重复运行可指定 OutputDirectory 和 Port。

Electron 参考：分别在两个终端启动 fixture 和工具：

~~~powershell
node test/fixtures/testSshServer.mjs 22349 build/terminal-electron-fixture
# 另一个终端
$env:OFS_TERMINAL_STRESS_PORT='22349'
$env:OFS_TERMINAL_STRESS_SECONDS='60'
node_modules/electron/dist/electron.exe scripts/terminalElectronReference.cjs
~~~

无需安装远端软件。真实 WAN、物理断网、多显示器 DPI、IME 和完整主窗口操作未被本地 fixture 全面覆盖，发布流程仍应执行相应专项检查。此次没有发布。
