# 多实例窗口：实现与验收

本次实现采用一个 Electron 主进程对应一个完整应用实例。普通启动继续保持单实例，只有显式新窗口请求才创建独立进程。当前代码提供 Windows 预览能力；不代表已经完成正式发布验收。

## 启动入口与开放范围

| 环境 | 默认启动 | 显式新窗口 |
| --- | --- | --- |
| Windows 源码开发运行 | 聚焦已有默认实例 | 设置 → 常规 → 允许多实例窗口（预览） |
| Windows 打包程序 | 聚焦已有默认实例 | 默认关闭，可在设置中开启 |
| macOS / Linux | 单实例 | 暂不开放 |

Windows 可用入口：应用左上角名称菜单中的“打开新窗口”、`Ctrl+Shift+N`、命令行 `--new-instance`。打包程序开启开关后还会注册任务栏 Jump List 的“打开新窗口”。普通桌面/开始菜单快捷方式保持原行为。

在“设置 → 常规”开启“允许多实例窗口（预览）”后，无需重启即可使用上述入口。此偏好持久保存并同步到其他窗口。关闭开关只禁止新建实例，已有窗口、会话和传输继续运行；再运行带 `--new-instance` 的快捷方式会按普通启动聚焦已有窗口。旧版 `OFS_MULTI_INSTANCE_PREVIEW` 环境变量不再覆盖设置。

源码预览（先在第一个窗口开启开关）：

```powershell
npm run build
& .\node_modules\electron\dist\electron.exe .
& .\node_modules\electron\dist\electron.exe . --new-instance
```

安装包也可在开启开关后用命令行新建窗口：

```powershell
& '实际安装路径\OpenFinalShell.exe'
& '实际安装路径\OpenFinalShell.exe' --new-instance
```

多实例仍为 Windows 预览功能；macOS/Linux 的设置项禁用，直到对应平台验收完成。

## 进程与窗口隔离

- `InstanceContext` 生成不可复用 UUID，持有主窗口、编辑器、关闭状态与资源注册表。
- SSH、RDP、传输、监控、端口转发、LAN Sync、认证提示管理器均归属当前进程的资源表。AI 请求表同样为进程私有内存。
- 一个进程只允许一个应用实例。保留模块导出的管理器访问方式，因为独立进程本身已隔离模块内存；不引入同进程多个主窗口。
- IPC 只接受已注册窗口的主 frame，并校验应用页面地址。renderer 不能指定其他实例作为请求目标。
- 终端数据、RDP 端口/帧、传输进度、AI 增量只发送给所属窗口。主窗口和它自己的编辑器仅共享必要的低频事件。
- RDP 原有 generation / Worker identity 和手动重连隔离保持不变，日志附加实例 UUID。
- 关闭时先处理编辑器未保存内容，再拒绝新 IPC、取消本实例任务、关闭 SSH/RDP、等待传输释放、停止控制连接并关闭数据库。其他实例继续运行。

## 共享存储与凭据

所有实例共享 `userData` 下的 SQLite 与 Vault。数据库启用 WAL，锁等待为 500 ms、最多三次尝试；超限返回可读的 `DATABASE_BUSY`。事务使用 `BEGIN IMMEDIATE`，嵌套事务使用 savepoint。

配置读取会检查数据库当前内容；修改在事务内重新读取，避免将启动时缓存整体写回。连接、分组、AI 服务、代理和私钥编辑使用版本校验；旧版本返回 `CONFIG_CONFLICT`，不先改写凭据。设置按修改的部分与提交前快照比较。初始化、旧 JSON 导入、加密迁移和默认记录生成均在事务内再次检查迁移标记。

Windows 的 Electron `safeStorage` 还依赖 Chromium `Local State` 中的系统保护密钥。直接为每个进程分配空的 Chromium 数据目录，会导致实例间无法解密凭据，因此：

1. 以共享 `userData/Local State` 中的 `os_crypt` 元数据作为稳定来源。
2. 在 `app.ready` 前，仅将系统保护后的密钥元数据写入本实例 `instances/<UUID>/Local State`；不复制明文密钥、Token 或缓存。
3. 全新安装通过 PID 引导锁串行初始化密钥；其他首次启动进程最多等待 30 秒。
4. 已有密文但共享密钥元数据丢失时明确中止启动，避免生成不匹配的替代密钥。

renderer 使用实例专属内存 session；窗口尺寸写入 `instances/<UUID>/window-state.json`。普通启动的窗口另存默认布局供下次普通启动使用；显式窗口不覆盖它。日志为 `main-<UUID>.log`，打包传输临时目录为 `%TEMP%/ofs-pack/<UUID>`，传输残片文件名也包含实例 UUID。队列和当前标签不跨重启恢复；同一运行实例内支持暂停续传。

## 配置刷新和更新协调

每个进程建立带随机鉴权值的 Windows named pipe（其他平台的内部实现为 Unix socket）。控制通道只允许聚焦、心跳、配置 revision、更新操作、活动数量与退出请求。配置内容、终端字节、文件字节、密码和 Token 不通过此通道传输。

SQLite 触发器维护配置 revision。每两秒检查变化并发送通知；接收方校验数据库 revision、去重，再重新查询自己的配置列表。通知中的来源 UUID 表示发送通知的实例。窗口激活、设置页打开及 30 秒刷新用于恢复遗漏通知，不替换已有会话对象或编辑中的连接/AI 草稿。

首个注册实例成为更新协调者。普通主实例退出后，存活实例通过事务重新选举并尝试接管默认启动锁。其他窗口的更新操作转发给协调者。安装前汇总所有窗口的会话、传输与转发数量，按原有确认流程处理。

安装协调期间禁止新实例注册。协调者请求其他窗口退出并检查 PID 真正消失；收到 ACK 不等于退出。超时列出仍在运行的 UUID/PID，取消安装门禁，不强制结束进程。编辑器取消退出后允许重试。安装器启动失败会释放门禁；异常中断后的门禁最长保留五分钟，新版以 `--updated` 启动时清除。

## 自动验证

```powershell
npm run typecheck
npm run check:i18n
npm test
npm run build
npm run smoke:multi-instance
```

`test/fixtures/multiInstanceSmoke.mjs` 使用独立临时配置目录、本机测试 SSH/SFTP 服务和模拟 AI 服务，不读取用户配置。它真正启动多个 Electron 进程，覆盖：

- 普通第二次启动退出，显式实例 PID/UUID 不同。
- 空目录同时首次启动，初始化后的共享配置与凭据能够互读。
- 不同连接并发保存、同一连接过期保存被拒、配置变更通知到达。
- SSH 终端数据、SFTP 队列与 AI 回答保持实例隔离。
- SFTP 上传/下载内容一致；关闭 A 时 B 正在传输的文件继续完成。
- A 退出后 B 的 SSH 继续可用，并接管普通启动；三个显式实例同时存活。
- 全部退出后重启，原连接配置和 Vault 中的 AI Token 仍可用。
- 关闭多实例开关后，IPC 和命令行不能继续多开，已有会话和传输继续运行；重新开启可立即新建窗口。
- 开启和关闭两种设置都在完整退出、重启后保留。
- 测试日志不包含 fixture 密码或 Token。

结果写入临时目录的 `report.json`；可设置 `OFS_MULTI_INSTANCE_REPORT` 指定另一份报告路径。Windows 发布工作流运行这套测试并上传报告。单元测试另覆盖 IPC sender 拒绝、事务回滚、真实 SQLite 锁竞争、控制消息白名单、协调者选举、等待 PID 退出、退出取消后的重试和安装超时。

2026-09-16 本机验证记录：类型检查、10 种语言检查和 Electron 生产构建通过；119 个测试文件通过、5 个按环境跳过，共 1689 项通过、37 项跳过。真实多进程脚本的 11 个场景全部通过，其中 B 的 16 MB SFTP 下载在 A 退出后完成且字节一致。本次结果不包含下表中的 RDP 与安装器实机验收，也不代表远程 CI 已执行。

2026-09-16 后续 CI 验证：v0.30.21 发布门禁的 1690 项测试与 11 个真实多进程场景通过，报告见 [desktop-release 35049114740](https://github.com/kexue-aihao/openfinalshell/actions/runs/35049114740)。主分支随后补充 Windows 标题栏颜色拒绝时的窗口启动回归测试，CI 共 1691 项通过、37 项跳过。v0.30.22 又验证了开关关闭时新建请求被拒绝、已有传输继续完成，以及开关状态重启后保留。以上结果仍不包含真实双 RDP 和安装器交互验收。

## 正式开放前的 Windows 验收

以下项目需要交互桌面、真实 RDP 目标或安装器，自动测试不能替代。尚未完成的项目必须保留为待验收，不能标记为通过。

| 场景 | 本轮状态 |
| --- | --- |
| 多进程启动、配置并发、共享 Windows Vault | 已在本机真实 Electron 进程验证 |
| SSH / SFTP / AI 隔离、关闭后存活、重启解密 | 已在本机使用测试服务验证 |
| 实际 Windows 任务栏右键打开新窗口 | 待打包程序交互验收 |
| 两窗口分别连接真实 SSH/RDP，画面、输入、剪贴板相互独立 | SSH 已自动验证；RDP 实机待验收 |
| 关闭一个窗口后另一个 RDP 会话持续可用 | 待真实 RDP 目标验收 |
| 非主窗口触发真实安装，所有 Worker 清理后安装成功 | 协调协议已自动验证；安装器待验收 |
| macOS/Linux 多实例菜单与安装更新 | 暂不开放，待各平台验收 |

实机顺序：正常启动 → 再次普通启动 → 任务栏新窗口 → 两窗口分别连接 SSH/RDP → 同时终端/SFTP/AI → 修改配置观察另一窗口刷新 → 关闭 A 验证 B 会话与传输 → 从 B 协调更新。记录应用版本、平台、每项结果和脱敏诊断日志后，再调整生产能力门禁。
